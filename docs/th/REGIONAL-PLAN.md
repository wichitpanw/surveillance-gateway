- สาย Regional ↔ Central ขาด: Regional และ Edge จังหวัดในภาคต้องยังทำงานต่อ Client ที่ชี้ Regional ต้องดูภาพสด/ย้อนหลังและสั่ง PTZ ตามสิทธิ์ได้โดยไม่ต้องพึ่ง Central
- ทดสอบแบบจำลองและแกนระบบให้ผ่านก่อนเปลี่ยน `:5273`; ห้ามล้าง production ระหว่างพัฒนา

## 1. ข้อตกลงตั้งต้น (จากเจ้าของระบบ)

- ชั้นดูแล: **ประเทศ → ภาค → จังหวัด → ไซต์** · ชั้นโปรแกรม: **Central → Regional → Edge (จังหวัด)** จังหวัดต่อตรงเข้าภาค
- ใช้ **6 ภาค**: กลาง (รวม กทม./ปริมณฑล), เหนือ, ตะวันออกเฉียงเหนือ, ตะวันออก, ตะวันตก, ใต้ · ไซต์ใช้ Edge แยกเครื่อง พร้อม Remark ระบุที่ตั้ง ไม่ใช้ Sub-edge
- องค์กร มีโครงข่ายถึงกันทั่วประเทศ · IP กล้องอาจซ้ำข้ามจังหวัด แต่ edge แต่ละจังหวัดออกแบบ IP ในไซต์ตัวเอง ระบบชั้นบนไม่เห็น IP กล้อง (ใช้ global ID / id ของกล้อง) จึงไม่ถือเป็นปัญหา
- **ยังไม่ทำ:** TLS, ล็อกอินกลาง (AD/SSO), บันทึกการเข้าดู, ตาราง escalation ของการแจ้งเตือน · ขนาดงาน (จำนวนไซต์/กล้อง/ผู้ใช้) ยังไม่แน่ ปรับเมื่อได้ข้อมูล

**หลักเดิมที่ไม่เปลี่ยน:** edge เป็นเจ้าของกล้องและรหัสกล้อง · Edge รับ AI จากต้นทาง · วิดีโอส่งขึ้นชั้นบนเมื่อมีคนดู แต่ event/JPEG ส่งตามตัวรับที่เปิดไว้ · global ID ห้ามเปลี่ยนหลังออกแล้วแต่ถ้าถูกลบก็หายไปด้วย · ภาพย้อนหลังดึงจากอุปกรณ์ที่ edge

## 2. กติกาใหม่ (ต้องแก้ ../CONTRIBUTING.md เมื่อทำ)

| โปรแกรม | แอดอะไร | ไม่ทำ |
|---|---|---|
| **Edge (จังหวัด)** | กล้อง (ONVIF / NVR / VMS ทุกชนิด) | แอด edge อื่น |
| **Regional (ภาค)** | **Edge จังหวัด** ในภาคของตัวเอง | แอดกล้องเอง (เหมือน central ปัจจุบัน) |
| **Central (ประเทศ)** | **Regional** เท่านั้น | แอดกล้องเอง |

- Regional คือ Gateway ที่ทำ **สองหน้าที่พร้อมกัน**: ฝั่งล่างทำตัวเป็น central ของภาค (รับ edge จังหวัด, ออก key/token ให้ Client ในภาค) ฝั่งบนทำตัวเป็น edge (ต่อ WebSocket ขึ้นหา central, ส่ง catalog / สถานะ / ภาพ)
- ห้ามมีวงวน: central แอด regional ได้ทางเดียว regional ห้ามแอด central หรือ regional อื่น
- หน้าเว็บของ regional ใช้ชุดเดียวกับ central (Live, Playback, Edge Nodes, API Clients) ไม่มีปุ่มเพิ่มกล้อง · AI Events รวมผลต้นทางพร้อมภาพและกรอง Edge/Group ได้

## 3. ข้อมูลไหลอย่างไร

```
กล้อง ─▶ Edge จังหวัด ─▶ Regional ─▶ Central ─▶ Client ระดับประเทศ
        (ถือรหัส,รับ AI)    (รวมทั้งภาค)   (รวมทั้งประเทศ)
                             └────────▶ Client ภายในภาค (ยังใช้ได้เมื่อสายไป Central ขาด)
```

| ข้อมูล | วิธี | หมายเหตุ |
|---|---|---|
| รายชื่อกล้อง (catalog) | edge → regional → central ทุก 10 นาที + แจ้งทันทีผ่านสายเมื่อเปลี่ยน | global ID ผ่านตามเดิม ห้ามออกใหม่ระหว่างทาง · สองชั้นซ้อนทำให้ล่าช้าได้ถึง ~20 นาที ถ้าไม่มีการแจ้งทันที |
| สถานะกล้อง (`reachable`) | ส่งต่อทีละชั้น | ชั้นล่างขาด = `null` ทั้งกิ่ง (ตรงกับกติกาเดิม) ไม่เขียนเป็น `false` |
| ภาพสด | go2rtc ซ้อนสามชั้น ส่งแบบ raw (ไม่ transcode) | fan-out ที่แต่ละชั้น: กล้องหนึ่งตัวข้ามสายระหว่างชั้นได้ครั้งเดียว ไม่ว่ามีกี่คนดู · ปิดต้นทางเมื่อไม่มีคนดู 60 วิ ต้องซ้อนกันถูกลำดับ |
| PTZ | rpc ซ้อน central → regional → edge | timeout ชั้นนอก > ชั้นใน + 2 วิ · ต้องเปิด `allow_ptz` ทั้งสองข้อ |
| ภาพย้อนหลัง | ช่วงเวลา/ภาพนิ่งผ่าน rpc ซ้อน · วิดีโอ: edge อัปโหลดเป็นสตรีมขึ้น regional แล้ว **regional ต่อท่อต่อขึ้น central** (ไม่พักดิสก์) | ต้องเขียนตัวต่อท่อใหม่ · timeout: ช่วงบันทึก 60 วิ, ภาพ 50 วิ |
| AI event | Edge → Regional → Central | รับผลจากต้นทางพร้อม JPEG; ไม่มี inference ทั้งสามชั้น |
| แจ้งเตือน edge หลุด | regional แจ้งจังหวัดของตัวเอง · central แจ้ง regional หลุด + จำนวนกล้องที่ไม่ทราบสถานะ | escalation ตามเวลาทำภายหลัง |
| อัปเดตโปรแกรม | central → regional → edge จังหวัด (regional เก็บแพ็กเกจที่เซ็นแล้วไว้แจกต่อ ตรวจ `sig` + `sig2` ซ้ำ) | ปล่อยเป็นรอบ: ภาคทดลอง → ภาคอื่น |
| ผู้ใช้/API key | แยกตามชั้น: regional มีผู้ใช้และออก API key ให้ Client ในภาคซึ่งต่อ `/api/v1` ของ Regional โดยตรง · central ออก key ให้ Client ระดับประเทศและกำหนดสิทธิ์รายภาค/จังหวัด | กลุ่มกล้องที่ตั้งเองเดิมใช้ต่อได้ |

## 4. โมเดลข้อมูล

- `ROLE` เพิ่มค่า `regional` (`server/shared/instance.js`) · ชื่อแอป **Surveillance Gateway Regional** · `/api/instance` และ `/health` รายงาน `role: regional`
- **ภาค:** `server/data/thai-region-groups.csv` (จังหวัด 2 หลัก → 6 ภาค) ใช้จัดสิทธิ์/สรุป · อิงการแบ่งของ [สำนักงานสถิติแห่งชาติ](https://www.nso.go.th/public/e-book/Statistical-Yearbook/SYB-2025/53/) โดยรวม กทม./ปริมณฑลกับภาคกลาง · **กล้องจาก VMS ไม่มีจังหวัดต้องตั้งก่อนนับสรุป**
- **เลข node (3 หลัก):** central เป็นเจ้าของเลขทั้งประเทศ · Regional ใช้เลขต้นบล็อก 100/200/... และ Edge ในภาคใช้เลข +1 ถึง +99 · 001–099 สงวนสำหรับของเดิม ไม่ออกซ้ำหลัง reset
- `camera_sources` เพิ่ม `remote_role`, `remote_region`, `node_block` · `cameras.id` ของกล้อง relay ใช้ hash คงที่จากเลข node + ID ชั้นล่างเพื่อไม่ถูกตัดจนชนกัน · `global ID` คงรูป `TH-<จังหวัด>-<node>-<ลำดับ>` ที่ Edge ออกครั้งเดียว
- จังหวัด/อำเภอ/ไซต์เป็นข้อมูลสถานที่สำหรับแสดงผลและค้นหา เช่น `ตัวอย่าง / อำเภอตัวอย่าง / ชุมสาย A`; ชื่อสถานที่ไม่เป็นส่วนของ `global ID` · ตารางไซต์ (รหัสชุมสาย ชื่อ พิกัด ประเภท) ทำภายหลังเมื่อรายละเอียดพร้อม

## 7. เกณฑ์ผ่าน

1. central เห็นกล้องจากสอง Edge ผ่านสอง Regional พร้อม global ID ที่ Edge ใหม่ออกให้ ไม่ซ้ำและไม่เปลี่ยนระหว่างทาง
2. ภาพสด main/sub ข้ามสามชั้นได้ · เปิดดู 3 client พร้อมกันแล้วกล้องข้ามสายระหว่างชั้นครั้งเดียว · ปิดหมดแล้วต้นทางปิดใน ~60–120 วิ
3. PTZ (DSS, Tiandy) ผ่านสองชั้นแล้วกล้องขยับจริง · `allow_ptz` ปิดที่ชั้นใดชั้นหนึ่ง = ถูกปฏิเสธ
4. ย้อนหลัง (ช่วงบันทึก, ภาพนิ่ง, วิดีโอ) ผ่านสองชั้น · ปิดหน้าต่างกลางทางแล้วไม่มี ffmpeg/ท่อค้าง
5. ตัด regional: central เห็นกล้องของภาคนั้นเป็น `null` ต่อกลับแล้วกลับมาเอง · ตัด edge จังหวัด: regional แจ้ง, central เห็นเฉพาะกิ่งนั้นเป็น `null`
6. อัปเดตแพ็กเกจส่งจาก central ถึง edge จังหวัดผ่าน regional ได้ · ลายเซ็นปลอม/รุ่นเก่าถูกปฏิเสธที่ทุกชั้น
7. `node --check`, eslint, build, และทดสอบด้วย DB ใหม่ผ่าน
8. Regional ออก API key แล้ว Windows Client ที่ชี้มาที่ Regional เข้า `/api/v1/health`, เห็นกล้องเฉพาะภาค, ดูสด/ย้อนหลัง/PTZ ตามสิทธิ์ key ได้; key ของ Central เห็นกล้องรวมทั้งประเทศตาม scope

## 8. ความเสี่ยงและข้อควรระวัง

- **:5273 เป็น production** ห้ามเปลี่ยน role ของ instance ที่มีกล้องจริงอยู่ในที่เดิม (ดูข้อ 6)

- **รุ่นไม่ตรงกัน:** central ใหม่กว่า regional ใหม่กว่า edge ระหว่างปล่อยอัปเดต · ต้องมีเลขรุ่นของ "โปรโตคอล" ใน hello และปฏิเสธเมื่อห่างเกินไป
- **สายภาคขาด:** ทั้งภาคเป็น `null` ที่ central (เป็นพฤติกรรมที่ตั้งใจ) ผู้ใช้ในภาคยังใช้ regional ของตัวเองได้
- **ไม่มี TLS:** สามชั้นข้ามเครือข่ายองค์กร ยังเป็นข้อความธรรมดา ตกลงพักไว้แล้ว แต่ต้องทำก่อนเปิดใช้จริงข้ามหลายไซต์
- **ความจุ:** ตัวเลขเดิม (NIC 1 Gbps ที่ central ≈ 45–60 คน/wall sub) ใช้กับ central ต่อไป regional ต้องคำนวณแยกตามจำนวนคนในภาค

## 9. ยังไม่ตัดสินใจ / รอข้อมูล

- จำนวนไซต์/กล้อง/ผู้ใช้ต่อภาค · สเปกเครื่อง regional (ต้องมี GPU ไหม — ถ้า client ถอดรหัสเอง ไม่ต้อง)
- ตารางไซต์ · ช่องทางและเวลาแจ้งเตือน · นโยบาย AI event ข้ามภาคเมื่อกลับมาทำ
- TLS / SSO / บันทึกการเข้าดู (พักไว้)
